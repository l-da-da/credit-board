# 额度看板

在 DSH 侧边栏底部加一个「额度」入口，点开是一个浮层看板，汇总五家客户端的签到状态和余额，并能一键触发签到。

## 看板里有什么

| 应用 | 余额 | 签到状态 |
| --- | --- | --- |
| WorkBuddy | 点头像读「积分余额」 | 调客户端自己的签到接口（等同点侧边栏那张「立即领取」卡片），没跑过时退回日志 |
| 豆包 | 总额度（「用豆包工作」页面的累计获得额度） | 读自动签到的运行结果，按账号列出 |
| CodeArts | 「积分用量」面板的积分余额 | 活动福利里的每日签到状态 |
| AStudio | 点左下角账号读「积分余额」 | 每日登录积分随登录自动发放（没有可点的签到按钮），脚本只保证当天登录过 |
| AutoClaw | 总积分 | 不参与签到 |

登录账号会与 `config.json` 的 `expectedAccounts` 比对，不一致时该行标红提示。

## 按钮

- **刷新余额**：在后台最小化启动各客户端，读取一次余额后自动关闭（约 30–60 秒）。
- **立即签到**：执行 `auto-checkin\run-checkin.ps1`，等同于计划任务的那次运行。
- **签到后保留客户端**：勾选后签到完不关闭客户端（豆包会带调试端口常驻，下次直接连上）；取消勾选则跑完就关。

## 依赖

面板通过本机 `http://127.0.0.1:47122` 读取数据，这个服务由计划任务 `DSH-CreditBoard` 在登录时启动；它只监听回环地址，不对外网开放。

数据来源：

- `auto-checkin\logs\last-result.json`（最近一次签到结果）
- `auto-checkin\logs\progress.json`（本次签到进行到哪一步，面板据此显示「正在签到：豆包…」）
- `auto-checkin\logs\balance.json`（余额采集快照）
- `~/.workbuddy/logs/main.log`（WorkBuddy 今日签到状态，接口拿不到时的兜底）

## 限制

- WorkBuddy 的积分余额需要点头像面板才能读到，采集时会做这个动作（窗口最小化）。
- WorkBuddy 不会「启动即领」：签到要走它自己的 `wb.account.checkinStatus()/checkin()` 接口，因此需要客户端带 `--remote-debugging-port=9533` 启动；已经开着但没带端口的实例会被重启一次（重启的那次签到完保持打开）。
- 豆包展示的是「用豆包工作」页面上的总额度（累计获得），剩余额度要去「设置 → 订阅与额度管理」看。
- AStudio 是 IDE，**不会**为了拿调试端口去重启正在用的实例：如果它开着但没带 `--remote-debugging-port=9535`，本次跳过（余额保持上次读数，不影响每日登录积分）。想让它也参与，可以在 `config.json` 里设 `"astudio": { "restartIfOpenWithoutPort": true }`。
- AStudio 的接入可以整体关掉：`config.json` 里 `"astudio": { "enabled": false }`，看板就不显示这一行；端口/路径也能改（`port`、`exe`）。
- 刷新余额会短暂启动客户端（最小化、不抢焦点），跑完自动关闭；你自己开着的应用不会被关。
- 面板「刷新余额 / 立即签到」只写 flag，由计划任务消费；`DSH-CheckinNow` 是长轮询（每 1.5 秒看一次，响应 ≤2 秒）。签到进度、上次各家的结果都会显示在面板上，排队超过 2 分钟会提示检查任务是否启用。
